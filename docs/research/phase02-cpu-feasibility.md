For a future ORC probe, compile an original IR function in the selected native ARM64 executor, resolve it, call it and compare the result with an independent known answer under the target signing configuration. Record mapping and publication behavior. Apple's documented Hardened Runtime JIT route uses `com.apple.security.cs.allow-jit` with `MAP_JIT`. Choose the applicable write-protection API and invalidate the instruction cache before executing newly written instructions. Verify the allocator and code publication path for the selected LLVM version under those rules. Class B applies to the documented Apple APIs. [Apple JIT porting guide](https://developer.apple.com/documentation/apple-silicon/porting-just-in-time-compilers-to-apple-silicon)

For fixed, immutable fixtures, incremental AOT could lift known entry points before runtime and link ARM64 code through the normal host toolchain. It adds control-flow discovery and artifact provenance requirements and still needs a policy for unresolved indirect targets and modified code. A later hybrid could keep the interpreter and translate measured hot blocks, with explicit exits that preserve registers, flags and precise fault location. Any cache must track guest code identity and mapping generation and invalidate translations before changed code can execute. Keep those paths experimental and removable without changing Track A.

Before broadening the guest instruction set, specify SIMD lane and upper-register effects, x87 precision and exceptions, SSE rounding and NaN behavior, and guest atomics and ordering with spec-derived litmus cases. Any parallel execution must preserve guest x86 ordering on ARM64 without assuming host TSO. Begin with deterministic single-thread execution, explicit guest traps and synthetic service yields. Guest stacks and fault state belong to the guest. Host signals and Darwin stack frames require separate mapping research. Keep guest addresses in checked software regions with distinct read, write and execute permissions. Query host page size at runtime and define any finer guest permissions in software. Xbox virtual-memory and ABI contracts remain unknown. ## X1 original fixture

Use a flat, immutable byte slice assembled from Xenora-authored x86-64 assembly, with a separate eight-byte output region addressed by guest RDI. Start RIP at the first instruction, initialize GPRs explicitly, and start with RFLAGS bit 1 set and the six arithmetic flags clear. Use a harness-defined terminal address immediately after the store, with entry to that address checked before fetch. No imports, stack, syscalls, SIMD or writable code are needed. The assembly specification is:

```asm
    mov eax, 0xffffffff
    add eax, 1
    cmp eax, 0
    jne store
    mov eax, 42
store:
    mov [rdi], rax
```

Use a second fixture variant that changes the immediate in the first instruction to `0xfffffffe`. The first variant falls through, executes six instructions, and ends with RAX = 42 and output bytes `2a 00 00 00 00 00 00 00`. CMP leaves ZF and PF set and CF, OF, SF and AF clear. The second takes the branch, executes five instructions, and ends with RAX = `0x00000000ffffffff` and output bytes `ff ff ff ff 00 00 00 00`. CMP leaves SF and PF set and ZF, CF, OF and AF clear. Check RIP, RDI and other GPRs, flags after ADD and CMP, and unchanged bytes outside the store. Check ADD against the independent derivation as well: the wrap case sets CF, PF, AF and ZF, and the non-wrap case sets SF and PF. Mask assertions to the defined arithmetic flags. [AMD64 instruction manual](https://docs.amd.com/v/u/en-US/24594_3.37)

Cap code at 64 bytes and execution at 16 retired instructions, and use a checked guest-address range for each memory access. Restrict decoding to the fixture's instruction forms and the branch to a forward decoded boundary. Negative tests cover an unsupported opcode, truncated operand, branch into an operand, budget exhaustion under a reduced test budget, out-of-range output and a store crossing the output boundary. Record fault kind and guest RIP and require faulting instructions to leave registers and output unchanged from pre-instruction state. Record assembler version, native tool architecture, fixture bytes and hash, initial state, trace and terminal state. R2 derives expected results directly from the public ISA and fixture and checks that the oracle is independent of production decode and execution. R1 checks provenance, native binary evidence and claim scope.
