# Native issue archive

**Preserved history, not a backlog.** BetterXen's active direction is the CrossOver-based hybrid architecture ([roadmap](../roadmap.md)). The independent native implementation is paused indefinitely; this page replaces its GitHub issue backlog so the work can be found without occupying the active Issues tab. Native source code, tests, benchmarks, Git history and attribution are untouched. Resuming native work needs an explicit maintainer decision ([native roadmap](native-roadmap.md)).

Every issue below keeps its full text, comments and attribution on GitHub and can be reopened; closing used the reason "not planned". Issues imported from the earlier Xenora repository say so in their first lines, and their original author is recorded below. Excerpts are the first sentence of the issue's objective, not a summary of acceptance criteria.

## Native pieces hybrid development might use

Nothing in the native backlog is a prerequisite for the hybrid phases. One possible reuse is already noted: the original compiled C guest fixture of #313/#330 could serve as one authorized test workload for hybrid baselines ([#364](https://github.com/MacosPorters/betterxen/issues/364)). If hybrid work needs any other native component, it should be filed as a focused hybrid issue.

## Findings preserved from discussions

- **Remill evaluation ([#324](https://github.com/MacosPorters/betterxen/issues/324)).** An isolated, native ARM64 evaluation pinned Remill at `66c488c9911fd9b368e4d0c9647d74239f8bba8b`. Five original AMD64 traces lifted and ran with 32 passing case/path checks. A second pass recorded eight floating-point mismatches (guest rounding, MXCSR sticky flags, denormals-are-zeros, an unmasked precision exception) and a loop that needed external termination; the decision was to retain the existing CPU path, and the failing gate was left failing. An adapter design was written. Published on branch `research/remill-arm64` (commit `e50268d8723a29a365a36c6b665db6d4e3733f6b`; `experiments/remill/`). Local test results, not CI; no independent acceptance.
- **VIctory shader-compiler feasibility ([#261](https://github.com/MacosPorters/betterxen/issues/261)).** Local experiments (`experiments/victory-native/`, uncommitted, on a local branch) built a pinned shader compiler natively, translated original gfx1030 fixtures to DXIL, converted them with Apple's Metal shader converter and checked native Metal readback (a 4x4 pixel probe and a 32-word buffer transform) on an M4, plus a review of an upstream Xenora snapshot (114 tests passed). Those materials depend on VIctory-family source whose input provenance the [upstream registry](upstream-registry.md) does not clear for reuse; they are not part of this branch and nothing from them is adopted.
- **PortWatch review and native plan ([#298](https://github.com/MacosPorters/betterxen/issues/298), [PR #308](https://github.com/MacosPorters/betterxen/pull/308)).** Produced [portwatch-native-macos.md](portwatch-native-macos.md) and a seven-phase native plan (open PR #308, which replaces the README X1 to X25 table). The native plan is superseded by the hybrid roadmap; the PortWatch screening facts remain useful.
- **Metal buffer pool ([#130](https://github.com/MacosPorters/betterxen/issues/130)).** A bounded completed-buffer pool imported from upstream Xenora commit `4f3d0ae1ca44ff5e01e569eab07f776af43d2f8e` (author Vedant Dadhich, GPL-3.0-or-later attribution retained) passed 58 native tests locally with a negative control; a pipeline-selection fixture was added under [#315](https://github.com/MacosPorters/betterxen/issues/315). Local branch `integration/xenora-metal-pool`, not pushed.
- **C++ unwind prerequisite ([#343](https://github.com/MacosPorters/betterxen/issues/343)).** An isolated `experiments/cpp-unwind` workspace adapting restricted prolog-restoration logic from upstream Xenora (Swastick Chowdhury, SPDX notice retained); local branch `integration/cpp-unwind`, not pushed.

Local branches and worktrees named above are not on GitHub; their owners decide whether to publish them.
