# Shader inputs and provenance

**Scope:** the original native fixture input contract below remains preserved. The active hybrid bridge supplies original compute machine code and explicit root layouts to `victory-shader`; no console-container corpus was validated. See the [integration report](victory-shader-integration.md). Parser presence is not compatibility evidence.

Use original assembly assembled by `llvm-mc` for `gfx1030`. Preserve its exact tool version and target options, byte range and endianness, object and extracted code digests, and independently derived outputs. Pass the validated code range and explicit stage and architecture through the Xenora fixture interface. Use a symbol or a declared code range when extracting from an object so alignment bytes and padding do not enter execution. An AMDHSA object also has a separate documented code object ABI (CLAIM-LLVM-GFX1030). [LLVM AMDGPU usage and code object layout](https://llvm.org/docs/AMDGPUUsage.html)

The documented DirectX container can carry either DXBC or DXIL shader parts. Its outer `DXBC` magic identifies the container structure. A DXIL program part contains versioned LLVM bitcode (CLAIM-DXCONTAINER-PAYLOAD). A self-authored HLSL shader compiled with public DXC remains a possible separate input path for later work. Apple's shader converter documents DXIL input to a Metal library (CLAIM-MSC-DXIL). [LLVM DXContainer](https://llvm.org/docs/DirectX/DXContainer.html), [Microsoft DXIL format](https://github.com/microsoft/DirectXShaderCompiler/blob/915bf4f93a254d920b4bcab75b6b1c622eacd816/docs/DXIL.rst#dxil-container-format), [Apple shader converter](https://developer.apple.com/metal/shader-converter/#your-first-conversion)

The public HlslCompile sample identifies a serialized console pipeline path (CLAIM-XBOX-ACO-SAMPLE). A public binary layout and validation contract for that path remain unresolved (CLAIM-XBOX-ISA-ABI). The synthetic input contract requires no Xbox toolchain or game assets.
