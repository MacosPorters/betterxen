# Optional allocator reference assessment

Reviewed 2026-11-26: AMD's [D3D12 Memory Allocator](https://github.com/GPUOpen-LibrariesAndSDKs/D3D12MemoryAllocator/tree/600949266be004553f74c9ef809384380a9d44cf), exact commit `600949266be004553f74c9ef809384380a9d44cf`; the pinned header reports version 3.3.0. This is a public, general-purpose GPUOpen allocation library, with no game/console material used in this assessment.

The exact files reviewed were [LICENSE.txt](https://github.com/GPUOpen-LibrariesAndSDKs/D3D12MemoryAllocator/blob/600949266be004553f74c9ef809384380a9d44cf/LICENSE.txt), [include/D3D12MemAlloc.h](https://github.com/GPUOpen-LibrariesAndSDKs/D3D12MemoryAllocator/blob/600949266be004553f74c9ef809384380a9d44cf/include/D3D12MemAlloc.h) (Git blob `b685a5cd6188519606efaf039cd88c2faffa261a`) and [src/D3D12MemAlloc.cpp](https://github.com/GPUOpen-LibrariesAndSDKs/D3D12MemoryAllocator/blob/600949266be004553f74c9ef809384380a9d44cf/src/D3D12MemAlloc.cpp) (blob `b7ba60a3a4deb0ed466b235b7c5298f91ba5c976`). Both source files carry the full AMD 2019–2026 MIT notice. The MIT grant permits use/modification/distribution while requiring preservation of its notice; it is compatible with inclusion in a GPL-3.0-or-later work under those obligations. This does not license CrossOver/D3DMetal/Rosetta or change their external status.

No source from this project is copied, compiled, linked, modified or adopted here. A's small first-fit trace allocator is original experimental code, not an alternative production allocator. Exact registry/reuse-matrix entries and preserved upstream notices are required before any future source integration; that would be a separately scoped decision.

| Requirement | Pinned source/API assessment | What remains unmeasured |
| --- | --- | --- |
| CUSTOM WB/WC L0 pools | POOL_DESC accepts D3D12_HEAP_PROPERTIES and heap flags; configurable block size/counts provide a plausible fit. | CreatePool/resource behavior under this exact CrossOver/D3DMetal build. |
| Placed buffers/textures | Existing allocator handles resource allocation alignment and heap-tier separation; alias resources are documented. | Our mixed/RT/depth cases through the allocator, not merely raw D3D12. |
| Pool bounds and accounting | Explicit block sizing and max counts can bound reservations; detailed statistics distinguish allocations, blocks and unused ranges. | Memory cost and latency against the A trace; its budget reports are DXGI estimates, not physical residency or BetterXen's unified title budget. |
| Fragmentation | Multiple allocation algorithms/statistics and defragmentation support exist. | BetterXen workloads, fixed-pointer constraints and migration cost. Moving a guest-visible mapped allocation cannot silently preserve pointer identity. |
| Fence retirement | Caller must ensure GPU use is complete before freeing/reassigning allocation/resource storage. Library allocation ownership is not a substitute for application queue/fence tracking. | Multi-queue retirement integration and stress. |
| Inverted CPU ownership | Resource Map remains a public D3D12 operation; allocator metadata cannot add requested CPU-VA or arbitrary scatter/section alias semantics. | No evidence that this library solves the infeasible rows in the [ownership matrix](inverted-ownership.md). |
| Portability/toolchain | Header has a path for externally supplied D3D12-compatible headers; implementation explicitly handles MinGW variants. | No local allocator build/runtime test performed. |

Recommendation: retain it as the first reuse candidate if production pooling is justified, then run the same trace against an externally built pinned version before selecting it. Raw-D3D12 pooling results cannot be presented as this allocator's performance, fragmentation quality or CrossOver compatibility. Documentation/source assessment is class D (project evidence); public D3D12 contracts are class B. Independent review and runtime qualification remain pending.
